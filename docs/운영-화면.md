# 운영 화면 쓰는 법

운영 화면(`/admin`)은 FSK 운영 담당이 씁니다. 고객 화면과 비밀번호가 따로이고, 들어올 때 이름을 적으면 규칙을 바꾼 기록에 그 이름이 남습니다. 처음 띄우면 이 PC 에서만 운영 비밀번호를 정할 수 있습니다.

탭은 현황, 규칙, 학습, 이력, 설정의 다섯 개입니다. 규칙과 학습 탭 옆의 숫자는 아직 판정하지 않은 후보 수입니다.

## 현황

기간(최근 7일, 14일, 30일, 90일)을 고르면 그 사이에 들어온 서류 묶음을 봅니다.

| 칸 | 뜻 |
|---|---|
| 맨 위 숫자 여섯 개 | 처리한 묶음, 엑셀로 나간 품목 줄, 「빠진 줄 의심」, 사람이 고친 묶음과 확정, 규칙이 채운 칸, 묶음 하나의 평균 처리 시간 |
| 서류별 처리 | 묶음 안의 쪽을 운송장, 인보이스, 포장명세서, 통관표, 약관으로 가른 쪽 수와 종류마다 읽는 방법 |
| 들어온 서류 묶음 | 묶음마다 공급사, 서류 구성과 쪽 수, 품목 줄, 빠짐 검사 결과, 규칙이 채운 칸, 사람이 고친 칸, 걸린 시간 |

묶음 줄을 누르면 오른쪽에 자세히 보기가 열립니다. 쪽마다 어떤 서류로 갈랐는지, 처리 단계와 걸린 시간, 빠짐 검사 네 가지의 결과, 쓰인 규칙과 그 규칙이 채운 칸, 사람이 고친 칸(전과 후)이 나옵니다. 고객이 「빠진 줄 의심」을 어떻게 판정했는지도 여기서 봅니다.

## 규칙

왼쪽에서 범위를 고릅니다. 맨 위가 공통 규칙이고 그 아래가 공급사입니다. 공급사는 처음 보는 송하인이 들어오면 저절로 생기고(「자동으로 생김」 표시), 「공급사 추가」로 직접 만들 수도 있습니다. 공급사를 알아보는 낱말(송하인 이름의 일부 같은 것)은 공급사 정보 고치기에서 더합니다.

| 종류 | 하는 일 | 쓰이는 때 |
|---|---|---|
| 코드 사전 | 품명이나 부품 번호가 같은 줄의 SAP 코드, 자재 코드, 원산지를 채웁니다 | 판독이 끝난 뒤 |
| 값 바꾸기 | 단위와 원산지 표기를 G-ERP 에 맞게 바꿉니다(예: PCS 를 EA 로) | 판독이 끝난 뒤 |
| 열 이름 | 서류 표에서 칸을 찾는 열 이름을 더합니다 | 판독할 때 AI 지침에 더함 |
| 판독 지침 | 공급사 서류의 특징을 문장으로 알립니다 | 판독할 때 AI 지침에 더함 |
| 빠짐 검사 | 네 가지 검사를 켜고 끄며, 금액 허용 오차를 정합니다 | 판독이 끝난 뒤 |
| 필수 칸 | 비어 있으면 확인 화면에 주의로 표시할 G-ERP 열입니다 | 확인 화면 |

같은 자리에 공통 규칙과 공급사 규칙이 둘 다 있으면 공급사 규칙을 씁니다. 공급사 범위를 열면 아래에 「이 공급사에도 쓰이는 공통 규칙」이 함께 나와서, 그 공급사에 실제로 쓰이는 규칙 전체를 한 화면에서 확인합니다.

### 단계

| 표시 | 뜻 | 할 수 있는 일 |
|---|---|---|
| 후보 | 학습이 만든 규칙. 아직 판독에 쓰지 않습니다 | 반영, 거절 |
| 반영 | 다음 판독부터 쓰는 규칙. 화면에서 직접 더한 규칙은 바로 반영됩니다 | 끄기, 격상(공급사 규칙만), 지우기 |
| 꺼짐 | 잠시 쓰지 않는 규칙 | 켜기, 지우기 |
| 거절 | 쓰지 않기로 한 후보. 같은 수정이 다시 생겨도 후보로 올리지 않습니다 | 없음 |

격상은 공급사 규칙을 공통 규칙으로 올리는 일입니다. 올린 규칙에는 「(공급사)에서 격상」이 붙고, 다른 공급사에 있던 같은 규칙은 그대로 남으니 필요하면 따로 끕니다. 기본값으로 들어 있는 규칙은 지우지 않고 끕니다.

반영, 거절, 끄기, 격상, 지우기를 누르면 확인 창이 뜨고, 바꾼 까닭을 한 줄 적을 수 있습니다. 적은 까닭은 이력에 남습니다. 규칙 줄마다 적용 건수와 마지막으로 쓰인 때가 나와서, 쓰이지 않는 규칙을 골라 끌 수 있습니다.

### 빠짐 검사를 다룰 때

빠짐 검사는 품목 줄이 몰래 빠지는 일을 막는 마지막 장치입니다. 공통에서 끄지 않습니다. 어떤 공급사 서류에 포장명세서 줄이 인보이스 줄과 일부러 다르게 묶여 나온다면, 그 공급사 범위의 빠짐 검사 칸에서 그 검사만 끕니다. 금액 허용 오차도 공급사마다 따로 둘 수 있고, 「공통 따르기」를 누르면 공급사 설정을 지우고 공통 값으로 돌아갑니다.

## 학습

고객이 확인 화면에서 한 일로 규칙 후보를 만듭니다. 저절로 반영하지 않습니다.

| 고객이 한 일 | 생기는 후보 |
|---|---|
| SAP 코드, 자재 코드, 원산지 칸을 고침 | 코드 사전 후보(그 공급사, 그 품명) |
| 단위나 원산지 표기를 바꿈 | 값 바꾸기 후보 |
| 비어 있던 칸을 채웠는데 그 값이 서류 표의 어떤 열에 있었음 | 열 이름 후보(서류에서 찾은 열 이름) |
| 줄을 더함 | 판독 지침 후보(그 공급사 서류에서 줄을 빠뜨렸다는 알림) |
| 「빠진 줄 의심」을 「문제 없음」으로 판정 | 그 공급사에서 그 검사를 끄는 후보 |
| 확정 | 정답 자료로 저장해 다음 후보의 미리보기에 씀 |

후보 카드에는 규칙 문장, 근거(어느 묶음의 어느 줄을 누가 어떻게 고쳤는지), 미리보기가 나옵니다. 미리보기는 지금까지 확정하거나 엑셀로 받은 묶음에 이 규칙을 적용하면 몇 칸이 바뀌고, 그중 사람이 남긴 최종 값과 맞는 칸과 어긋나는 칸이 몇 개인지 셉니다. 어긋나는 칸이 있으면 반영하기 전에 범위나 값을 고칩니다.

반영된 공급사 규칙과 같은 내용이 다른 공급사에서도 후보나 규칙으로 나오면 「격상 제안」에 나옵니다. 여러 공급사에 두루 맞는 규칙이라는 뜻이므로, 격상해 공통 규칙으로 올립니다.

우시 서류는 공급사가 많지 않고 서류 꼴이 자주 바뀌지 않아서 후보가 자주 생기지는 않습니다. 후보가 생기면 탭에 숫자가 뜨므로, 주 한 번 정도 들어와 판정하면 됩니다.

## 이력

규칙을 만들고, 반영하고, 끄고, 격상하고, 지운 일과 공급사를 만들고 고친 일, 설정을 바꾼 일을 시간 순서로 남깁니다. 누가, 언제, 어떤 까닭으로 했는지가 함께 나옵니다. 위의 종류 단추로 고릅니다.

## 설정

| 항목 | 하는 일 |
|---|---|
| Claude 계정 | 판독에 쓰는 계정의 이메일, 로그인 방식, CLI 판을 보여 줍니다. 「시험 질문 보내기」로 실제 응답을 확인합니다 |
| 계정 폴더 | 한 PC 에서 여러 계정을 나눠 쓸 때 판독용 계정 폴더를 적습니다. 비우면 그 PC 의 기본 계정입니다 |
| 판독 모델 | 기본은 Sonnet 입니다. 바꾸면 다음 판독부터 쓰고, 바꾼 뒤에는 설치 점검으로 먼저 확인합니다 |
| 보관 기간 | 올린 서류와 결과를 지우는 일수입니다(기본 14일) |
| 비밀번호 | 고객 화면과 운영 화면의 비밀번호를 바꿉니다 |
| 규칙 옮기기 | 규칙과 공급사를 파일 하나로 내려받고, 다른 PC 에서 올립니다 |

### 자기 Claude 계정으로 쓰기

판독은 화면을 띄운 PC(또는 서버)에 로그인된 Claude 계정으로 돕니다. 따로 API 키를 넣지 않습니다.

1. Claude Code 를 설치합니다. Windows 는 PowerShell 에서 `irm https://claude.ai/install.ps1 | iex`, 맥과 리눅스는 `curl -fsSL https://claude.ai/install.sh | bash` 입니다.
2. 터미널에서 `claude` 를 실행해 자기 계정으로 로그인하고 끝냅니다.
3. `start.bat`(Windows) 또는 `./start.sh` 로 띄우면 로그인된 계정을 확인하고 이메일을 보여 줍니다.
4. 운영 화면 「설정」에서 「연결 다시 확인」을 눌러 자기 이메일이 보이는지 봅니다.

한 PC 에서 개인 계정과 판독용 계정을 나누려면 판독용 폴더로 따로 로그인한 뒤 그 경로를 「계정 폴더」에 넣습니다.

| 운영체제 | 판독용 폴더로 로그인 |
|---|---|
| Windows(PowerShell) | `$env:CLAUDE_CONFIG_DIR="$HOME\.claude-wuxi"; claude` |
| 맥, 리눅스 | `CLAUDE_CONFIG_DIR=~/.claude-wuxi claude` |

## 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| 판독이 오류로 멈추거나 설정의 Claude 계정에 「로그인이 필요합니다」가 뜸 | 「시험 질문 보내기」로 응답을 봅니다. 응답이 없으면 터미널에서 `claude` 로 다시 로그인합니다 |
| 규칙을 반영했는데 다음 판독에 안 쓰임 | 범위가 그 공급사인지, 엔진이 그 묶음을 그 공급사로 알아봤는지 현황 자세히 보기에서 봅니다. 공급사를 못 알아봤으면 공급사 정보에 알아보는 낱말을 더합니다 |
| 같은 공급사가 둘로 생김 | 송하인 이름이 서류마다 조금씩 다르기 때문입니다. 하나에 다른 쪽의 알아보는 낱말을 더하고, 남은 쪽은 규칙이 없으면 그대로 둡니다 |
| 「빠진 줄 의심」이 자주 뜸 | 자세히 보기에서 어느 검사가 걸렸는지 봅니다. 서류 특성 때문이면 그 공급사에서만 그 검사를 끕니다 |
| 운영 비밀번호를 잊음 | 서버 PC 에서 `python tools/wuxi_web.py set-admin-password` 로 다시 정합니다 |

## 저장되는 곳

모두 `WUXI_HOME`(기본 `work/`) 아래에 있고 Git 에는 올라가지 않습니다.

| 파일 | 내용 |
|---|---|
| `rules.json` | 운영 규칙과 공급사 |
| `rules_history.jsonl` | 이력 |
| `feedback.jsonl` | 학습 신호(고친 칸, 더한 줄, 판정, 확정) |
| `settings.json` | 설정 화면에서 바꾼 값 |
| `access.json`, `admin.json` | 비밀번호 해시 |
| `jobs/<작업>/` | 올린 서류와 판독 결과, 엑셀로 받을 때의 값(`final.json`), 확정한 값(`golden.json`) |

운영 규칙을 저장소 기본값으로 올리면 새로 설치한 PC 에서도 같은 규칙으로 시작합니다. `python tools/wuxi_rules.py export --to-default` 를 실행하고 `schema/rules_default.json` 을 커밋합니다.
