# 노트북에서 한 번에

회사 노트북의 Claude 가 처음부터 끝까지 따라 하는 순서입니다. 사용자는 노트북의 Claude 에게 아래 한 줄만 줍니다.

> GitHub commet/wuxi-ocr 을 C:/Users/SAMSUNG/wuxi-ocr 에 받고(이미 있으면 main 을 pull), 그 안의 docs/노트북에서-한-번에.md 대로 끝까지 해줘.

이 문서와 `tools/laptop_go.sh` 는 GitHub 에만 있고 사내 Git 으로는 보내지 않습니다(`.gitattributes`).

## 끝나면 되어 있는 것

| 일 | 끝난 상태 |
|---|---|
| 노트북에만 있던 우시 수정 | 사내 원격, 노트북의 갈래와 작업 폴더에서 이관(커밋 `e63db149`) 뒤에 바뀐 우시 파일이 모두 GitHub 에 들어가 있거나, 옮길 것이 아니라고 확인됨 |
| 새 판 확인 | 자동 시험, 실제 AI 판독 세 가지(글자, 스캔, 120줄), 노트북의 실제 고객 서류 5건이 통과. 예전 판 점검 결과가 있으면 건마다 줄 수를 견줌 |
| 사내 Git | `DT/KEROL_FMS_DOC_AI` master 의 `wuxi_ocr/` 가 GitHub main 과 같음 |
| 노트북에서 띄우기 | 새 판이 `C:/Users/SAMSUNG/wuxi-ocr` 에서 따로 떠 있고, 운영 화면 첫 화면에서 두 비밀번호를 정할 수 있음 |
| 보고 | docagent 쪽에 남은 우시 흔적, 이 PC 의 Claude 계정, Mattermost 봇이 쓰는 계정을 확인하는 법 |

## Claude 가 지킬 것

1. 사내 저장소 작업 폴더(`C:/Users/SAMSUNG/KEROL_FMS_DOC_AI`)의 갈래를 바꾸거나, 그 안의 파일을 고치거나 커밋하지 않습니다. 사내 Git 덮어쓰기는 스크립트가 옆에 따로 꺼낸 임시 폴더에서만 합니다.
2. docagent 코드와 문서(`src/docai` 등 `wuxi_ocr/` 밖)를 고치지 않습니다. 우시 흔적이 나오면 목록을 보여 주고 사용자에게 묻습니다.
3. 비밀 파일(`.env`, 키, 자격 증명, `C:\docai\bot.env`)은 읽거나 옮기지 않습니다. 저장소 안전장치가 막으면 우회하지 않고, 사용자에게 직접 봐 달라고 합니다.
4. 고객 서류 PDF 와 판독 결과를 GitHub 에 올리지 않습니다. 실제 서류는 그 자리에서 읽기만 합니다.
5. 사내 판의 숫자는 이관 때 같은 꼴의 가짜 값으로 바꾼 것입니다. 사내 쪽 수정을 GitHub 으로 옮길 때 운송장, PO, SAP 코드 같은 번호는 옮기지 않고 GitHub 쪽 값을 그대로 둡니다.
6. 단계가 멈추면 메시지대로 고치고 그 단계부터 다시 합니다. 고칠 수 없으면 지어내지 말고 무엇이 막혔는지 사용자에게 말합니다.

명령은 모두 Claude 의 Bash(Git Bash)에서 `C:/Users/SAMSUNG/wuxi-ocr` 를 현재 폴더로 두고 실행합니다. 사내 저장소가 다른 곳에 있으면 먼저 `export COMPANY_REPO=<경로>` 를 합니다.

## 0. 받기

```bash
git clone https://github.com/commet/wuxi-ocr C:/Users/SAMSUNG/wuxi-ocr
```

이미 있으면 main 으로 받아 옵니다.

```bash
git -C C:/Users/SAMSUNG/wuxi-ocr checkout main && git -C C:/Users/SAMSUNG/wuxi-ocr pull --ff-only
```

비공개 저장소라 GitHub 로그인 창이 뜰 수 있습니다. 사용자가 로그인하면 이어 갑니다.

## 1. check: 노트북에만 있는 수정 찾기

```bash
tools/laptop_go.sh check
```

GitHub 판과 사내 저장소를 받아 오고, 이관 뒤 사내 쪽에서 바뀐 `wuxi_ocr/` 파일을 GitHub 판과 견줍니다. 내용이 같거나 숫자만 다른 파일(사내 판에서 번호를 가린 차이)은 저절로 넘어갑니다. 마지막 줄이 「통과」면 2단계로 갑니다.

「확인 필요」가 나오면 목록의 번호마다 `work/laptop/review/` 에 자료가 있습니다.

| 이유 | 볼 것 | 할 일 |
|---|---|---|
| 내용이 다름 | `NN-사내변경.patch`(이관 뒤 사내 쪽에서 바꾼 것), `NN-사내판.txt` | GitHub 의 같은 파일에 그 수정이 이미 들어 있으면(같은 뜻이면 글자가 달라도 됨) 옮길 것이 없습니다. 없으면 GitHub 파일에 손으로 옮깁니다. 번호는 옮기지 않습니다 |
| 사내에만 있음 | `NN-사내판.txt` | 우시 앱에 필요한 코드, 시험, 문서면 GitHub 에 같은 경로로 넣습니다. 잠깐 쓴 파일, 고객 자료, 비밀값이면 넣지 않습니다 |
| 사내에서 지웠는데 GitHub 에 있음 | `git -C <사내> log --oneline origin/master -- <경로>` | 일부러 지운 것이면 GitHub 에서도 지웁니다 |
| 이관 커밋이 없는 갈래에 wuxi_ocr 수정이 있음 | `git -C <사내> log --oneline <갈래> -- wuxi_ocr` | 대개 이관 전의 옛 작업입니다. GitHub 보다 새로운 수정이 없으면 옮길 것이 없습니다 |

판단이 서지 않는 수정은 patch 를 사용자에게 보여 주고 묻습니다. GitHub 에 옮겼으면 아래 순서로 올립니다.

```bash
tools/laptop_go.sh setup
```

```bash
git add -A && git commit -m "노트북에만 있던 우시 수정을 옮긴다" && git push origin main
```

`setup` 은 가상환경을 만들고 자동 시험을 돌립니다. 시험이 통과해야 커밋합니다. GitHub 에 올릴 권한이 없으면 멈추고 사용자에게 알립니다.

옮겼거나 옮길 것이 없다고 확인한 파일은 확인했다고 적고 check 를 다시 실행합니다. 갈래 항목은 갈래 이름을 줍니다.

```bash
tools/laptop_go.sh ack wuxi_ocr/tools/예시.py origin/옛갈래
```

check 출력의 「docagent 쪽 우시 흔적」과 「이 PC 의 Claude 계정」은 고치지 않고 마지막 보고에 넣습니다.

## 2. setup: 설치와 자동 시험

```bash
tools/laptop_go.sh setup
```

파이썬 3.11 이상으로 `.venv` 를 만들고 패키지를 받은 뒤 자동 시험을 돌립니다. 파이썬이 없으면 사용자에게 설치를 부탁합니다(python.org 의 Windows 설치본, 「Add to PATH」 선택).

## 3. verify: 실제 판독 확인

5분에서 10분 걸리므로 Bash 의 뒤에서 돌리기(run_in_background)로 실행하고 끝나기를 기다립니다.

```bash
tools/laptop_go.sh verify
```

| 확인 | 통과 기준 |
|---|---|
| 가짜 묶음 세 가지(글자 PDF, 스캔 PDF, 120줄 세 장) | 정답과 칸마다 같음 |
| 노트북의 실제 고객 서류 5건(`KEROL_FMS_DOC_AI/wuxi_ocr/work/docs_raw/hx`) | 오류 없이 읽음. 예전 점검 결과(`work/batch/*.json`)가 있으면 건마다 인보이스 줄 수가 줄지 않음 |

「빠진 줄 의심」은 실패가 아닙니다. 서류 특성일 수 있으니 건수만 보고합니다. 「줄이 줄어듦」이 나오면 새 판에서 줄이 빠진 것일 수 있으므로 4단계로 가지 않고 사용자에게 보고합니다. Claude 로그인 오류가 나오면 사용자에게 `claude` 로 다시 로그인해 달라고 합니다.

## 4. sync: 사내 Git 덮어쓰기

```bash
tools/laptop_go.sh sync
```

1단계부터 3단계가 지금의 GitHub 판으로 통과했을 때만 돕니다. 사내 master 를 사내 저장소 옆의 임시 폴더에 따로 꺼내 `wuxi_ocr/` 만 GitHub 판으로 바꾸고, `wuxi_ocr/` 밖이 바뀌지 않았는지 본 뒤 커밋해 사내 원격 master 에 올립니다. 사내에서만 추적하던 비밀번호 해시는 남깁니다. 노트북 작업 폴더는 그대로입니다.

check 뒤에 누가 사내 master 에 올렸으면 check 부터 다시 하라고 멈춥니다. 올리기가 거절되면(권한, 사내망) 메시지를 그대로 보고합니다.

## 5. serve: 노트북에서 띄우기

뒤에서 돌리기로 실행합니다. 끝내지 않고 둡니다.

```bash
tools/laptop_go.sh serve
```

8767 이 쓰이고 있으면 다음 빈 포트를 씁니다. 작업 폴더는 `C:/Users/SAMSUNG/wuxi-ocr/work` 이고, 예전 판의 작업 폴더와 비밀번호는 건드리지 않습니다. 사용자에게 아래를 알립니다.

1. 브라우저에서 운영 화면(`http://127.0.0.1:<포트>/admin`)을 열면 처음 화면이 나옵니다. 이름, 운영 비밀번호, 고객 화면 비밀번호를 한 번에 정합니다. 이 화면은 이 PC 에서만 뜹니다. 고객 화면 비밀번호를 예전과 같게 두려면 같은 값을 넣습니다.
2. 고객 화면에서 `work/samples/sample/text/` 의 가짜 PDF 를 올려 엑셀까지 받고, 운영 화면 「현황」에 그 묶음이 보이는지 봅니다.
